# 스마트 버티포트 통합 관제

단일 X500 관제 흐름을 시연하는 Streamlit 대시보드입니다. DEMO에서 임무 단계와 로컬 이동 경로를 시뮬레이션하고, 브라우저 웹캠의 FOD 탐지 결과로 착륙 안전을 판단합니다. 실기체와 PX4 SITL 상태는 미연동으로 표시합니다.

## 설치와 실행

Windows 64비트 Python 3.12를 권장합니다. 저장소 루트에서 실행합니다. 이미 준비된 가상환경을 사용할 경우 생성 명령은 건너뜁니다.

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r .\vertiport_dashboard\requirements.txt
.\.venv\Scripts\python.exe -m streamlit run .\vertiport_dashboard\app.py
```

브라우저에서 `http://localhost:8501`을 엽니다. 카메라에는 브라우저 권한과 localhost 또는 HTTPS가 필요합니다. 원격 연결 환경에 따라 WebRTC ICE 설정이 필요할 수 있습니다. 앱은 `train_model/weights/best.pt`를 우선 사용하고, 해당 파일이 없으면 `vertiport_dashboard/models/best.pt`를 확인합니다. 모델 클래스는 `{0: "FOD"}`입니다.

## 조작 순서

1. 오른쪽 **실시간 영상 분석**에서 START를 누릅니다. 유효한 분석의 FOD 개수, 최고 신뢰도, 마지막 분석 시각과 AI 처리시간이 표시됩니다. 기본 분석 간격은 0.5초, 유효시간은 3초입니다.
2. 중앙 3D 뷰어에서 지면을 클릭하거나 X/Y/Z를 직접 입력합니다. **목표 좌표 전송**을 눌러 DEMO 목표에 적용합니다. 목표를 적용할 수 있는 단계는 대기와 착륙 완료입니다. 2D 지도도 선택할 수 있습니다. [3D 디지털 트윈 사용법](../docs/3D_DIGITAL_TWIN.md)
3. 왼쪽에서 **사전 점검 → 임무 시작**을 누릅니다. Hover 도달 뒤 **패드 위치 확인**으로 설정된 패드를 운영자가 확인합니다. **착륙 요청**은 안전 조건이 충족될 때까지 대기하며, 충족되면 시뮬레이션이 중심 정렬과 하강을 진행합니다. 일시정지, 재개 및 취소도 DEMO 상태에만 적용됩니다.
4. 사이드바에서 기체 상태를 직접 지정하거나 기존 정상·배터리 부족·긴급 시뮬레이터를 실행할 수 있습니다. 지도 위치는 DEMO 임무 상태가, 하단 고도와 배터리는 선택한 DEMO 텔레메트리 공급자가 생성합니다.

**이미지 업로드**는 JPG/JPEG/PNG를 분석하고 박스와 신뢰도를 표시합니다. 이미지 분석 결과의 유효시간은 60초이며, 실시간 착륙 판단에는 사용하지 않습니다.

## 로컬 좌표와 안전 판단

- 지도는 로컬 미터 좌표입니다. 원점 `(0, 0, 0)`은 지상의 패드 중심이며, X는 오른쪽, Y는 위쪽, Z는 지상에서 위로 증가합니다. 지도 범위는 X/Y 각각 ±10 m, 목표 고도는 0~20 m입니다. 이 좌표는 GPS, Gazebo 좌표 또는 PX4 NED로 변환되지 않습니다.
- Landing Pad는 지도에 설정된 영역이며 운영자가 DEMO 임무에서 확인합니다. 별도의 패드 인식 모델은 연결되어 있지 않습니다.
- **HOLD**는 유효한 카메라 분석이 없거나, FOD 미탐지 상태에서 패드·기체·통신 조건을 확인해야 할 때 표시합니다. 카메라 연결 종료 또는 결과 만료 시 FOD 개수는 **미확인**입니다.
- **UNSAFE**는 유효 분석에서 FOD가 하나 이상 탐지됐을 때 표시합니다. **SAFE**는 유효한 FOD 0개 결과와 DEMO 패드 확인, 사전 점검 통과, 정상 기체 상태 및 최신 카메라 경로가 함께 확인됐을 때 표시합니다. 외부 MAVLink 연결 검증은 후속 단계입니다.
- 배터리 20% 미만과 긴급 상태는 기체 경고에도 별도로 표시합니다. SAFE를 잃으면 시뮬레이션 하강이 보류되며 재요청이 필요합니다.

## 기록과 구성

- 기존 열 구조의 CSV는 `vertiport_dashboard/logs/event_log.csv`에 저장됩니다. 임무 시작, 목표 좌표, Hover, 패드 확인, 착륙 판단, 하강, 완료 및 카메라 연결 오류 등을 최근 이벤트에서 확인할 수 있습니다.
- 실시간 첫 FOD 탐지의 프레임을 박스가 표시된 JPEG로 `vertiport_dashboard/data/fod_snapshots/`에 저장합니다. 같은 탐지가 이어지면 한 장만 저장하며, 유효한 미탐지가 3초 이상 이어진 뒤 재탐지하면 새로 기록합니다. JSON 메타데이터와 CSV 파일명으로 연결되며, 사진 갤러리에서 상세 보기와 다운로드를 제공합니다.
- `app.py`는 관제 화면과 이벤트를 연결합니다. `mission_controller.py`는 DEMO 단계, `map_controller.py`와 `map_component/`는 좌표 검증과 클릭 입력을 담당합니다. `telemetry_provider.py`는 기존 드론 시뮬레이터를 감싸는 데이터 공급 경계입니다. `smart_vertiport/landing_policy.py`의 단일 기체용 FOD 판단과 기존 다중 기체 알고리즘은 별도 경로입니다.

PX4 SITL·Gazebo·MAVSDK와 외부 Bridge 서버는 팀 환경에서 구축합니다. 대시보드는 HTTP 계약을 통해 연결하고, 미수신 GPS·MAVLink 정보는 비워 둡니다. Jetson은 필수 장비가 아닙니다.

## GAZEBO Bridge와 Mock

데이터 모드에서 **GAZEBO**를 선택하면 HTTP Bridge의 준비 상태와 최신 텔레메트리를 조회합니다. 기본 주소는 `http://127.0.0.1:8765`이며 `VERTIPORT_BRIDGE_URL`로 변경합니다. 서버 없이 검증할 때는 **Mock Bridge**와 **Mock 테스트 좌표 변환 사용**을 선택합니다. DEMO는 로컬 시뮬레이션을 유지하며 REAL은 미연동으로 표시됩니다.

실제 HTTP 명령은 기본 조회 전용 설정에서 꺼져 있습니다. 팀에서 승인한 시뮬레이션에 대해 별도 설정을 적용하면 목표 좌표, Hover, 임무 취소 요청을 Bridge에 전달할 수 있습니다. 실제 HTTP 착륙 요청은 하향 영상과 착륙 안전 판단 연동을 검증할 때까지 차단됩니다. 주소, 좌표 변환, JSON 예시 및 오류 처리는 [Bridge 팀 인터페이스](../docs/GAZEBO_BRIDGE_INTERFACE.md)를 참고하세요.
