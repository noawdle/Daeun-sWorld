# 버티포트 3D 디지털 트윈

대시보드 중앙은 기본으로 3D 공간을 엽니다. 지면에는 1m 격자와 좌표축, 설정된 원점의 H 표식 착륙패드가 있습니다. 이동 기록은 DEMO에서 청색 실선, GAZEBO에서 청록색 실선입니다. 황색 점선은 현재 위치에서 선택 목표까지의 안내선입니다. 시작점·현재 지상 투영점·목표는 별도 마커로 표시합니다. 하단에는 좌표, 자세, 고도, 비행 모드, Armed, 거리, 샘플 시각 및 FOD 상태가 표시됩니다.

## 실행 및 의존성

저장소 루트에서 실행합니다. 기존 Python 의존성을 그대로 사용합니다.

```powershell
.\.venv\Scripts\python.exe -m streamlit run .\vertiport_dashboard\app.py
```

Three.js **0.180.0**과 같은 릴리스의 OrbitControls를 `vertiport_dashboard/map_component/vendor/three-0.180.0/`에 포함했습니다. 브라우저는 Streamlit 컴포넌트의 로컬 정적 파일을 사용합니다. MIT 라이선스는 같은 경로에 들어 있습니다. WebGL 2를 사용할 수 없거나 렌더러 초기화에 실패하면 2D 화면으로 전환합니다. **2D / 3D** 버튼으로 수동 전환할 수도 있습니다.

## 카메라와 목표 지정

| 조작 | 동작 |
| --- | --- |
| 왼쪽 드래그 | 중심점을 기준으로 회전 |
| 오른쪽 드래그 | 평행 이동 |
| 휠 | 확대·축소 |
| 단일 클릭 | 지면 교점의 X/Y를 목표 입력에 반영 |
| 더블 클릭 | 지면 교점을 카메라 중심으로 이동 |
| TOP / FRONT / SIDE / ISOMETRIC | 평행 투영 시점 전환 |
| FOLLOW DRONE / FREE VIEW | 기체 추적 시작·해제 |
| RESET VIEW / FIT ALL | 기본 시점 복원 / 패드·격자·경로·목표 전체 보기 |

지면 클릭은 Three.js Raycaster로 교점을 계산합니다. Z는 기존 숫자 입력으로 선택합니다. 클릭은 기존 Streamlit 컴포넌트 메시지의 `{x,y,id}`를 사용하며, Python이 지도 범위를 다시 확인합니다. 실제 명령 요청은 기존 **목표 좌표 전송** 버튼에서만 평가합니다.

## 좌표와 자세

로컬 원점은 Landing Pad 중심이고 단위는 m입니다. X는 오른쪽, Y는 위쪽, Z는 지상에서 위로 증가합니다. 뷰어는 `(x, y, z) → (x, z, -y)`로 변환하며 Raycast에는 역변환을 적용합니다. 기체, 패드, 목표, 경로는 모두 같은 변환을 사용합니다. Bridge ENU 위치는 팀이 입력한 로컬↔Bridge 설정으로 먼저 역변환합니다.

Bridge 자세는 선택 필드 `attitude_convention: "ENU_FLU_RZYX_DEG"`가 있고 세 각도가 모두 유효할 때 반영합니다. 이 값은 ENU 월드, FLU 기체(+X 전방, +Y 왼쪽, +Z 위), 도 단위, 월드 방향으로 기체 벡터를 변환하는 `Rz(yaw) Ry(pitch) Rx(roll)`을 뜻합니다. 로컬 Yaw는 Bridge Yaw에서 로컬→Bridge 변환의 회전값을 뺍니다. Three.js에서는 기체 기저를 동일하게 변환해 쿼터니언을 계산합니다. NED, FRD 또는 다른 회전 관례는 Bridge에서 변환한 뒤 보내야 합니다. 태그나 각도가 빠지면 자세 수치는 미확인으로 표시하고, 기체 메시에는 기본 자세를 사용합니다. 실제 Bridge 자세 규격의 합의 및 검증은 후속 작업입니다.

## 기체와 데이터 연결

- X500 형태의 모델은 중앙 몸체, 암 4개, 모터·프로펠러 4개, 착륙 스키드와 청록색 전방 표식으로 구성합니다. `twin.js`의 `MODEL_SCALE`은 시각화 크기이며 실측 치수가 아닙니다.
- DEMO는 기존 임무 컨트롤러의 위치와 단계별 경로를 사용합니다. 시뮬레이션 진행 방향을 자세에 반영하고 Armed 상태에서 프로펠러를 회전합니다.
- GAZEBO는 기존 Provider의 유효 위치·자세·고도·비행 모드·Armed와 배터리 데이터를 사용합니다. Mock Bridge 응답은 화면에 별도로 표시됩니다. 변환 미설정, 연결 종료, 만료 또는 위치 누락 시 모델을 숨깁니다. 경로는 정상 수신한 위치만 기록하며 최대 180점입니다. 수신이 끊긴 뒤에는 새 궤적을 시작합니다.
- 기체는 두 수신 샘플 사이를 보간합니다. 화면이 예측 위치를 추가하지 않습니다. 기체 모델과 카메라 상태는 분리되어 있어 FREE VIEW에서는 위치 갱신 중에도 사용자의 시점이 유지됩니다.

## FOD와 남은 연동

FOD 패널은 기존 YOLO 분석 개수, 최고 신뢰도, 분석 시각과 SAFE/HOLD/UNSAFE를 표시합니다. 데이터가 끊기거나 만료되면 미확인으로 전환됩니다. 카메라 영상의 박스에는 월드 위치가 없으므로 지면에 FOD 마커를 만들지 않습니다. 별도 월드 위치가 필요하면 카메라 자세·보정·좌표 원천을 팀과 합의해야 합니다.

패드는 설정 좌표로 표시합니다. 실제 Gazebo 연결, Landing Pad AI 인식, Bridge 하향 영상과 FOD 안전 판단 연결은 후속 단계입니다. 기존 HTTP 명령·착륙 제한은 그대로 적용합니다. [Bridge 인터페이스](GAZEBO_BRIDGE_INTERFACE.md)
